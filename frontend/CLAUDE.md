# Frontend Guidelines for Claude Code

This frontend is connected to Lovable. Follow these rules in addition to the repository-wide rules in the root `CLAUDE.md`.

## Lovable Workflow

- Preserve the existing Lovable integration and project structure.
- Avoid rewriting published Git history. Do not force-push, rebase, amend, or squash commits that are already published through Lovable.
- Keep the branch in a working state because pushed commits sync back to Lovable.
- Frontend changes are usually small and feature-specific. Do not make broad UI or architecture changes unless explicitly requested.

## Scope

- Modify only the requested frontend feature.
- Do not change unrelated routes, shared components, styles, or mock data.
- If a shared component or route change is unavoidable, explain the affected features before proceeding.
- Do not edit `src/routeTree.gen.ts` manually; it is generated by the TanStack Router tooling.

## Frontend Conventions

- Use TanStack Start file-based routing under `src/routes/`.
- Reuse components from `src/components/ui/` before adding new UI primitives.
- Keep temporary demo data clearly separated from live API data.
- When connecting a screen to the backend, handle loading, empty, error, and stale-data states.
- Use the backend schema and actual API response as the basis for frontend types.

## Package Manager and Verification

- Use `npm` as the project-standard package manager.
- Run commands from the `frontend/` directory:

```sh
npm install
npm run lint
npm run build
```

- Do not claim a check passed unless it was actually run.
