# ER Guardian Pro

AI 기반 응급실 통합 지원 시스템의 시연용 웹 프로토타입을 만들어줘.

이 프로젝트는 응급실 환자의 상태 악화를 조기에 예측하고, 환자와 의료진의 대화를 바탕으로 응급진료기록 작성, 기록 누락 검사, 주진단 및 질병코드 추천을 지원하는 시스템이다.

이번 구현의 목적은 실제 AI 모델이나 병원 EMR을 완성하는 것이 아니라, 프로젝트 발표에서 서비스의 핵심 기능과 전체 사용 흐름을 직관적으로 보여주는 것이다. 모든 데이터는 가상의 샘플 데이터와 Mock API로 구현한다.

5. 환자용 상태 안내 화면

별도의 “환자 모니터 화면 미리보기” 버튼을 제공한다.

환자에게는 의료진용 상세 수치나 어려운 의학 용어를 그대로 보여주지 않는다.

환자용 화면에는 다음 내용을 크게 표시한다.

“현재 의료진의 재평가가 필요한 상태입니다.”

“안전을 위해 의료진의 안내 없이 응급실을 떠나지 마세요.”

“담당 의료진이 현재 상태를 확인하고 있습니다.”

현재 진료 진행 단계

예상 대기 상태

의료진 호출 버튼

빨간색을 과도하게 사용해 환자를 공포스럽게 만들지 말고, 주황색과 네이비 계열을 사용해 주의가 필요하다는 점을 전달한다.

환자에게 “사망 위험”이나 구체적인 악화 확률은 표시하지 않는다.

누락된 항목은 빨간색, 확인이 필요한 항목은 노란색으로 표시한다.

오른쪽에 “AI 추천 추가 질문” 카드를 배치한다.

“알레르기가 있는 약이나 주사를 맞고 이상 반응이 있었던 적이 있나요?”

“현재 복용 중인 약의 이름과 마지막 복용시간을 알고 계신가요?”

“흡연 중이거나 과거에 흡연한 적이 있나요?”

각 질문 옆에 “기록에 추가” 버튼을 만든다.

상단에는 의무기록 완성도를 78%로 표시하고, 누락 항목을 보완하면 완성도가 올라가도록 구현한다.

10. 구현 조건

React와 TypeScript 기반으로 구현

Tailwind CSS와 shadcn/ui 컴포넌트 활용

차트는 Recharts 사용

모든 기능은 Mock 데이터로 동작

버튼을 눌렀을 때 결과가 나타나도록 상태 변화와 인터랙션 구현

모든 페이지가 정상적으로 이동하도록 라우팅 구성

단순한 정적 화면이 아니라 발표자가 클릭하면서 전체 서비스 흐름을 보여줄 수 있는 프로토타입으로 제작

모바일보다는 1440px 데스크톱 화면에 최적화

숫자와 차트가 너무 많아 산만해지지 않도록 핵심 정보의 시각적 우선순위를 명확하게 구성

의료진 화면과 환자용 화면의 정보 수준을 명확히 구분

오탈자 없이 자연스러운 한글 문구 사용

먼저 전체 대시보드와 김민수 환자의 상세 모니터링 화면을 완성하고, 이후 AI 진료기록, 기록 누락 검사, 진단코드 추천 화면을 순서대로 구현해줘.

STEP 1. AI 응급진료기록 작성

환자 상세 화면 상단에 기본 환자 정보를 표시해주세요.

예:

김민수 / 남 72세 / KTAS 2 / 내원시간 14:32

Vital 정보는 별도의 카드로 표시합니다.

예:

* BP 158/94 mmHg

* HR 108/min

* RR 22/min

* BT 36.7℃

* SpO₂ 94%

* Mental Status: Alert

Vital 정보는 AI가 대화에서 생성하는 정보가 아니라 기존 시스템/EMR 정보처럼 표시해주세요.

2-1. 환자-의료진 대화 영역

왼쪽 또는 상단에 대화 기록 영역을 배치합니다.

버튼:

* 녹음 시작

* 녹음 일시정지

* 녹음 종료

* 샘플 대화 불러오기

현재는 실제 STT를 구현하지 않고 샘플 대화 불러오기 버튼을 누르면 아래 대화가 나타나도록 합니다.

의료진: 어디가 불편해서 오셨나요?

환자: 한 시간 전부터 가슴이 쥐어짜듯이 아파요.

의료진: 통증이 다른 곳으로 퍼지나요?

환자: 왼쪽 팔과 턱까지 아픈 것 같아요.

의료진: 통증이 0점에서 10점이면 몇 점 정도인가요?

환자: 한 8점 정도 되는 것 같아요.

의료진: 숨이 차거나 식은땀이 나나요?

환자: 숨이 조금 차고 식은땀도 났어요.

의료진: 이전에도 이런 증상이 있었나요?

환자: 이렇게 심한 건 처음입니다.

의료진: 평소 앓고 있는 병이 있으세요?

환자: 고혈압이랑 당뇨가 있어요.

의료진: 복용 중인 약이 있나요?

환자: 혈압약과 당뇨약을 먹고 있습니다.

의료진: 약물 알레르기는 있나요?

환자: 잘 모르겠습니다.

2-2. AI 기록 생성

대화 영역 오른쪽 또는 아래에 “AI 응급기록 생성” 버튼을 배치합니다.

버튼을 누르면 AI가 대화 내용에서 확인된 정보만 이용하여 응급진료기록 초안을 작성하도록 합니다.

매우 중요한 생성 원칙

AI는 대화에서 확인되지 않은 내용을 절대 임의로 생성하지 않습니다.

* 대화에 있는 내용 → 기록

* 명확하게 “없다”고 한 내용 → 없음으로 기록

* 언급되지 않은 내용 → 빈칸 또는 “미확인”

* 불확실한 내용 → “확인 필요”

절대로 AI가 의료정보를 추측해서 채우면 안 됩니다.

예:

대화에 흡연 여부가 없다면

X `흡연력: 없음`

O `흡연력:` 빈칸

또는

O `흡연력: 미확인`

2-3. 응급기록 양식

AI가 생성하는 응급진료기록은 아래 항목으로 구성합니다.

주호소

환자가 응급실에 오게 된 가장 중요한 증상.

예:

`흉통`

통증평가

NRS 점수, 위치, 양상, 방사통 등 대화에서 확인된 내용만 기록.

예:

`NRS 8, 쥐어짜는 양상의 흉통, 좌측 팔 및 턱으로 방사`

현병력

현재 증상의 발생 시점과 경과 및 동반 증상을 의료기록 형태의 짧은 문장으로 정리합니다.

예:

`내원 약 1시간 전부터 발생한 쥐어짜는 양상의 흉통으로 내원함. 좌측 팔과 턱으로 방사되며 호흡곤란 및 발한 동반함.`

과거력

기저질환, 수술력, 알레르기, 복용약 등을 포함합니다.

예:

`HTN, DM / 혈압약 및 당뇨약 복용 중 / 약물 알레르기 확인 필요`

사회력

흡연, 음주 등.

대화에서 언급되지 않았다면 빈칸으로 둡니다.

계통문진

대화에서 확인된 증상을 (+), (-) 형태 또는 간단한 목록으로 기록합니다.

예:

`Chest pain (+), Dyspnea (+), Sweating (+)`

언급되지 않은 증상을 임의로 `(-)` 처리하면 안 됩니다.

신체검진

의료진이 실제로 진찰하면서 말하거나 입력한 객관적인 신체검진 결과만 기록합니다.

샘플 대화에 신체검진 내용이 없으므로 초기 상태는 빈칸 또는 `미확인`으로 표시합니다.

추정진단

현재까지 확인된 증상과 기록을 바탕으로 의료진이 고려할 수 있는 진단.

예:

`Acute coronary syndrome 의증`

단, AI가 자동 확정하는 것이 아니라 의료진 검토가 필요한 추천 형태로 표시합니다.

응급진료결과

귀가 / 입원 / 전원 / 사망 / 진료 진행 중 등을 기록합니다.

초기에는:

`진료 진행 중`

각 기록 항목은 모두 의료진이 직접 수정할 수 있는 textarea 또는 input 형태로 구현해주세요.

하단 버튼:

* 임시저장

* 다음: 누락 검사

STEP 2. 기록 누락 검사 및 보완

이 기능은 단순히 빈칸만 찾는 것이 아니라,

현재 환자의 주호소와 기록 내용을 기준으로 추가 확인이 필요한 임상정보를 찾아주는 기능으로 표현해주세요.

중요 AI 데이터 처리 원칙

전체 기능에서 다음 원칙을 반드시 반영해주세요.

1. AI Hallucination 방지

AI가 환자-의료진 대화에 존재하지 않는 임상정보를 임의 생성하지 않도록 UI와 데이터 흐름을 설계합니다.

2. 없음과 미확인을 구분

예:

의료진: “알레르기 있으세요?”

환자: “없어요.”

→ `없음`

질문 자체가 없었음

→ `미확인`

두 상태를 구분합니다.

3. 환자 발화와 객관적 신체검진을 구분

환자:

“배를 누르면 아파요.”

→ 증상/현병력 정보

의료진:

“우하복부 압통이 있습니다.”

→ 신체검진

환자 발언만으로 신체검진 결과를 생성하지 않습니다.

4. 진단코드는 자동 확정하지 않음

AI는 KCD 후보를 추천할 뿐이며,

`AI 추천 → 의료진 선택 → 의료진 최종 인증`

과정을 거쳐야 최종 저장됩니다.

전체 데모 시연 흐름

최종적으로 아래 순서가 자연스럽게 연결되도록 모든 버튼과 화면 이동을 구현해주세요.

1. AI 진료기록 메뉴 클릭

2. 응급실 환자 목록 확인

3. 위험도가 가장 높은 김민수 환자 선택

4. 환자 기본정보 및 Vital 확인

5. 샘플 환자-의료진 대화 불러오기

6. AI 응급기록 생성

7. 생성된 기록 확인 및 필요한 경우 수정

8. 임시저장

9. 기록 누락 검사 실행

10. AI가 누락/확인 필요 항목 표시

11. AI 추천 추가 질문 확인

12. 의료진이 누락 항목 직접 보완

13. 필수 누락 항목이 모두 작성된 경우에만 다음 단계 이동

14. 추정진단 기반 KCD-9차 코드 후보 3개 확인

15. 진단코드 1개 선택

16. 최종 응급진료기록 Summary 확인

17. 의사 검토 및 인증

18. 최종 저장 완료

UI/UX 요구사항

기존 ER:ON 화면 디자인과 색상, 카드 스타일, 사이드바 구조는 최대한 유지합니다.

의료진이 짧은 시간 안에 확인할 수 있도록 화면은 복잡하지 않고 전문적인 병원 EMR 스타일로 구성해주세요.

특히 다음 정보는 시각적으로 명확하게 구분합니다.

* 작성 완료 → 초록 계열

* 확인 필요 → 노랑/주황 계열

* 누락 → 빨강 계열

* AI 추천 → 별도 AI 배지 또는 아이콘

* 의료진 최종 확정 → 체크 아이콘

단, 색상만으로 상태를 구분하지 말고 텍스트 또는 아이콘을 함께 사용해주세요.

모든 화면은 데스크톱 기준으로 먼저 최적화하고, 발표 시연 시 화면 이동이 자연스럽게 이어지도록 구현해주세요.

기존 구현된 기능 중 환자 모니터링과 악화 예측 기능은 삭제하지 말고 유지해주세요.

이번 수정의 핵심은 기존 AI 진료기록 기능을

“대화 기반 기록 생성 → 기록 완전성 검사 → 누락 정보 보완 → KCD 추천 → 최종 기록 → 의사 인증”

이라는 하나의 명확한 Workflow로 변경하는 것입니다.

구현된  ER:ON 응급의료센터 서비스를 아래의 요구사항에 맞게 수정해주세요. 기존 전체 UI 의 톤앤 매너, 디자인 시스템은 유지하되 환자 모니터링 기능의 화면 구조와 사용 흐름을 아래와 같이 변경해주세요.
